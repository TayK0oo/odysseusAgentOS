<decisions>
## Implementation Decisions

### Autonomie et supervision
- **Niveau d'autonomie:** supervisée avec paramètre configurable. L'humain supervise, n'exécute pas (P10 "ON the loop").
- **Déclencheur d'intervention humaine:** matrice de risque. Le système évalue dynamiquement le niveau de risque de chaque action (destructif, nouveau service tiers, budget dépassé) et escalade au besoin. Configurable par niveau.
- **Approbation longue durée:** via le bus de pensée + Gateway. Workflow émet événement → Gateway notifie (web, email, Discord) → signal humain → reprise automatique.

### Bus de pensée (cheminement de pensée)
- **Architecture:** event-driven simple. Émet des événements à chaque transition de phase (CLASSIFY→KNOW→PLAN→BUILD→QUALITY→AUTOEVAL→MEMORY_OBSERVE).
- **Modules SFD = subscribers.** Chaque module s'abonne aux phases pertinentes. Découplage total: ajout/retrait sans toucher la boucle.
- **Implémentation:** décorateurs Python `@on_phase("BUILD")`, bus interne asynchrone. Pas de dépendance externe (pas LangGraph, pas Temporal pour le bus).
- **Cheminement complet:** [Préférences] → CLASSIFY → [Recherche conversations] → KNOW → PLAN → [Exécution durable] → BUILD → QUALITY → AUTOEVAL → [Mémoire+Rétention] → MEMORY_OBSERVE → [Modalité sortie]

### Context Engine
- **Forme:** module dédié `src/context_engine/` avec sous-modules (aggregator, filter, compactor, notepad, thread_tracker, preference_injector).
- **Compaction:** seuil en % de la fenêtre de contexte du modèle (défaut 80%). Déclenchement automatique. Résumé par appel LLM léger (Haiku).
- **Filtrage:** similarité sémantique (embeddings) × filtre par phase × quota configurable (défaut 10 entrées).
- **Bloc-notes externalisé:** base vectorielle ChromaDB. Chaque décision = document avec embedding. Requêtable sémantiquement.

### Mémoire avec provenance
- **Périmètre v1:** taxonomie complète (profile, topics, areas, people, preferences) + tags [stated]/[observed]/[inferred] + CRUD versionné.
- **Stockage:** Fichiers Markdown (source de vérité, Git) + ChromaDB (index sémantique) + Graphify (relations entre concepts).
- **Versionnage:** `if_version` = hash SHA-256 tronqué du contenu du fichier. Recalculé à chaque écriture. Contrôle de concurrence: rejet si hash ne correspond pas.

### Exécution durable
- **Moteur:** custom Python + SQLite. Zéro dépendance externe. Workflows = classes Python. État persistant en base.
- **Périmètre:** seuil de durée/type configurable. Défaut: actions > 5s, appels outils externes, écritures.
- **Primitives à implémenter:** retry policies (max_attempts, backoff), compensation saga (ordre inverse), signaux d'approbation.

### Multi-agent
- **Posture:** actif et conçu pour évoluer. Le Chef d'orchestre peut déléguer aux sous-agents.
- **Garde-fous:** les 3 critères du §5.1.2 (protection contexte, parallélisation, spécialisation) restent mesurés et tracés, mais n'empêchent pas la délégation.
- **Sous-agents:** spécialisés par contexte (pas par métier), instanciés dynamiquement, contexte filtré.

### Ordre d'implémentation
1. Bus de pensée event-driven
2. Exécution durable (Custom SQLite)
3. Mémoire avec provenance (MD + ChromaDB + Graphify)
4. Préférences utilisateur
5. Sortie visuelle et multimodalité

### Kill-switches
- **Deux classes:** modules cœur stables (testés, approuvés) → ON par défaut. Modules expérimentaux → OFF par défaut.
- Chaque nouveau module SFD est livré avec son kill-switch.

### Sortie visuelle
- **Visualiseur:** HTML/SVG inline + Kroki (déjà dans la stack). Rendu dans iframes sandboxées.
- **Déclencheur:** patterns + mots-clés (rapide) puis décision LLM (confirmation). Deux étages.
- **Modules de design:** chaque module (diagram, mockup, chart, etc.) = un skill (SKILL.md) chargé avant génération.

### Claude's Discretion
- Paramètres de seuil exacts (durée pour exécution durable, quota pour filtrage contexte)
- Choix du modèle de compaction (Haiku par défaut)
- Structure exacte des événements du bus de pensée
</decisions>

## Existing Code Insights

### Reusable Assets
- **CanonicalLoop** (7 phases, gated OFF): squelette pour le bus de pensée. Déjà codé, testé.
- **ChromaDB** (port 8100, Docker): base vectorielle existante pour index mémoire et bloc-notes.
- **Kroki** (port 8700, Docker): rendu de diagrammes Mermaid/PlantUML déjà intégré.
- **Meilisearch** (port 7700, gated): full-text search pour recherche conversations.
- **Graphify** (port 9750, gated): graphe sémantique pour relations mémoire.
- **Kill-switch system** (38 switches): infrastructure existante pour activation progressive.
- **MCP servers** (6 built-in): extensibilité déjà en place.

### Established Patterns
- Architecture "câblé mais dormant": tout code nouveau = gated OFF par défaut
- Configuration YAML déclarative
- FastAPI + SSE streaming pour le frontend
- Docker Compose avec profils pour services optionnels

### Integration Points
- Le bus de pensée doit s'intégrer dans `src/agent_loop.py` ou le remplacer progressivement
- Les modules mémoire s'intègrent avec `services/memory/` (9 fichiers existants)
- L'observabilité s'intègre avec LangFuse + OpenTelemetry existants

<specifics>
## Specific Ideas

- Le cheminement de pensée doit être explicite et traçable: l'utilisateur doit pouvoir voir où en est le système dans les 7 phases
- La matrice de risque doit être configurable par l'admin: seuils par type d'action
- Le paramètre d'autonomie doit être ajustable par projet (pas global)
- Les fichiers Markdown de mémoire doivent être lisibles et éditables par un humain hors du système
</specifics>
